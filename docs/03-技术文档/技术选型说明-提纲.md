# 技术选型说明（提纲・方向一）

> 每个选型给对比表：候选 / 依据 / 结论 / 被否方案及理由。被否理由同时进 AI 使用报告（"我否决了什么"）。

## 1. 数据集选型

| 候选 | 依据 | 结论 |
|---|---|---|
| SIFT1M（128d/1M/官方 GT） | ANN-Benchmarks 标准底库；与现 128d 实验可比 | 主选 |
| GloVe-100 | 角度距离场景，补 cosine | 第二数据集 |
| Cohere/dbpedia-openai | 贴 RAG 真实嵌入分布 | 可选 |
| 均匀随机 | Beyer 1999 无意义性；Rand-Euclidean 反例 | 仅负向对照 |

## 2. 计时方式选型

| 候选 | 依据 | 结论 |
|---|---|---|
| fork-per-query psql（旧版） | 把进程启动+TCP+认证算进延迟，~12 ms 常数项 | 弃用 |
| 单长连接客户端计时 | 排除进程开销 | 采用 |
| `EXPLAIN (ANALYZE, TIMING ON)` 服务端计时 | 唯一能区分 CN/DN 执行时间的方式 | 采用（配合） |
| `pg_stat_statements` | 聚合视角，适合吞吐 | 辅助 |

## 3. 工具形态选型

shell + SQL 脚本（不写 C 扩展）：bench harness 进 pgvector 上游被拒（PR #863 先例），外部脚本是上游可接受的形态；也避免与方向二工具形态冲突（跨仓不重复）。

A 分布式 top-k over-fetch（推荐）/ B 代价模型修正（备选）/ C 迭代扫描分布式行为 / D 过滤后置分片放大——对比表见 T001 W3，选定后在此写决策记录。
