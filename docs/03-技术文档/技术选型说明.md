# OpenTenBase pgvector 查询优化技术选型说明

## 1. 选型原则

选型以可复现、可审查和不越过证据边界为优先级。任何候选必须能被单变量实验、固定数据、原始日志和正确性结果同时检验；只有满足预设门槛的候选才进入主结论。

## 2. 数据与计时

| 候选 | 决策 | 理由 |
|---|---|---|
| 均匀随机高维向量 | 仅作工程连通性/负向对照 | 不能证明 ANN 算法排序优势 |
| 固定 100,000×128d、200 queries | 采用主 run | 可哈希、可重复、与 perf 证据一致 |
| fork-per-query psql | 弃用 | 混入进程启动、认证和 TCP 常数 |
| 单长连接完整 workload | 采用 | 计时对象与查询批次一致 |
| 五次 ABBA | 采用 | 交错变体并保存负载快照 |
| 单次快跑 | 弃用 headline | 无法判断方向稳定性 |

主性能指标是五次完整 200-query workload 的均值和 QPS；逐查询 P95/P99 尚未采集，不能从均值推导。

## 3. 优化候选比较

| 候选 | 改动面 | 证据要求 | 本阶段决定 |
|---|---|---|---|
| A 分布式 top-k over-fetch | Coordinator 归并与 k' 函数 | N=1/2/4 分片 recall-QPS | 延期到 W3 |
| B `ivfflatcostestimate` 修正 | 代价模型与计划交叉点 | EXPLAIN/计划前后矩阵 | 延期到 W3 |
| C 迭代扫描分布式行为 | scan mode 与过滤选择率 | 过滤后置实测 | 延期到 W3 |
| D 过滤后置分片放大 | CN/DN 候选放大 | 低选择率 recall | 延期到 W3 |
| E 恢复自动向量化 flags | OpenTenBase Makefile/CFLAGS | 汇编、5 次 ABBA、recall | **选定并通过 G12** |

候选 E 的优势是变量最小且机制可见：上游已经提供自动向量化编译设计，OpenTenBase 只是静默丢失参数。修复后出现 `vfmadd231ps`，源码没有手写 `_mm*`/`__m*`；因此它符合“恢复平台能力”而不是“另写 SIMD 算法”的边界。

## 4. 负结果与保留控制

`ivfflat.query_work_mem` 能把临时块写入从 69,400 降为 0，但五次均值只改善 7.32%，低于 PLAN.md 预先写下的 10% 主门槛，故降级为辅助调优项。rescan 生命周期执行时间方向混合，保留 peak RSS 结果，不宣称延迟收益。第一轮负载漂移矩阵保留在归档中，不进入 headline。

## 5. 实现与交付形态

补丁以五个有序 format-patch 提交，canonical patch SHA256 固定；回归和 benchmark harness 与源码差异分离。图表脚本只读归档 CSV，构建脚本接受外部 `PYTHON_BIN`，不依赖工具运行时绝对路径。PR 正文包含动机、改动、测试和前后数据，AI 使用透明度放在独立报告而不是 PR 标题。

## 6. 后续选型门槛

W3 候选只有在同一主机、固定数据、至少三次重复、计划一致、recall 不下降且效果达到预设门槛后才可升级。若只改善某一配置或无法取得分布式原始日志，结果标为 inconclusive，不并入候选 E 的主结论。
