# IVFFlat 查询路径优化视频脚本

建议时长：6 分钟。画面素材来自 `docs/07-演示文稿/ivfflat-query-path-optimization.pptx` 与 `report/`。

## 0:00-0:25 开场

画面：标题页，随后切到 `-18.30%`。

旁白：

“这次实战解决的不是重新发明一个向量算法，而是让 OpenTenBase 中 pgvector 已有的能力真正生效。核心结果很简单：固定 workload 下，平均查询时间下降 18.30%，5 组配对全部更快，QPS 从 9.871 提升到 12.082。”

## 0:25-1:05 问题

画面：问题页，标出 `XX000`、32.80% 和临时块。

旁白：

“我们先从失败现象开始。IVFFlat rescan 会复用失效的 tuplesort 状态，触发 invalid tuplesort state；inner-product 热点占到 32.80% 的合计 perf 份额；另一个场景会产生 69,400 个临时块。三个现象看起来分散，实际都落在查询路径的生命周期和构建链路上。”

## 1:05-1:45 假设与实现

画面：三处改动页、实现流水线页。

旁白：

“改动分成三条线。第一条释放 rescan 路径中的旧 normalized value；第二条让 query_work_mem 控制路径内的排序内存；第三条恢复 OpenTenBase in-tree 构建对 pgvector CFLAGS 的传播。第三条不是手写 SIMD，而是恢复上游已经存在的自动向量化能力。”

## 1:45-2:25 方法

画面：ABBA 配对页。

旁白：

“实验使用 ABBA 交错配对。A 是 scalar，B 是构建标志恢复后的变体，顺序交错执行五对。变体共享固定种子、同一台主机和同一套 200 条查询；每个 so 的哈希都写入 run manifest。性能门槛在实验前就由 PLAN.md 规定为 10%，不是看完结果再倒推。”

## 2:25-3:15 性能结果

画面：SIMD 配对图，随后显示 `-18.30%`、`+22.40%`。

旁白：

“五组配对的趋势一致。标量均值是 20,261.376 毫秒，自动向量化均值是 16,552.993 毫秒，下降 18.30%。吞吐从 9.871 QPS 到 12.082 QPS，提升 22.40%。这条结果回答的是主性能问题，且 2,000 行 top-10 结果逐行一致。”

## 3:15-4:05 生命周期与调优

画面：rescan 内存图、perf 热点图、临时块图。

旁白：

“生命周期修复带来独立的稳定性证据：50,000 次 rescan 的峰值 RSS 增长降低 59.97%。perf 中 inner-product 合计占比从 32.80% 降到 17.37%。query_work_mem=64MB 后临时块从 69,400 降到零，但延迟改善只有 7.32%，低于预设门槛，所以我们把它记录为调优控制，不把它包装成主成果。”

## 4:05-4:50 正确性与证据

画面：正确性页、证据链页。

旁白：

“性能优化没有改变输出：exact/full-probes 对照为 2,000/2,000 一致，recall@10 等于 1.0。每个数字都能回到 CSV、原始日志或提交。第一次受主机负载干扰的 SIMD 尝试也保留在归档中，并明确排除，而不是删除不利证据。”

## 4:50-5:35 边界与贡献

画面：局限页、贡献页。

旁白：

“这份结果的适用域是固定 workload、单机、一个 Datanode、高 probes 和 Cosine。P95/P99、分布式 recall 和更大查询矩阵仍然延期。项目的可迁移贡献是两个平台级发现：rescan 生命周期缺陷，以及 OpenTenBase 构建链静默丢失上游自动向量化标志。”

## 5:35-6:00 收尾

画面：结论页，最后展示仓库目录。

旁白：

“最终交付不是一个孤立补丁，而是一条可复现链：源码、构建、运行、CSV、图表、PDF 和 AI 使用边界全部入库。下一步是带着固定补丁和证据进入上游维护者讨论。”
