> ⚠️ 旧稿写于 R001 评审之前，不知道四个坑（harness 开销、数据集有效性、HNSW 缺席、分布式缺失）。迁移时按下方修订结构重排，不是照抄。

## 1. 背景与问题（从需求调研报告 §2–§5 浓缩，两三段即可，不重复市场数字）

## 2. 目标与非目标

- 主目标：可信基线 → HNSW 全矩阵 → 真实优化（recall 不降 + 延迟降/吞吐升）→ 回归测试 → 对比报告。
- 非目标：不重写索引框架、不牺牲召回换延迟、不承诺跨硬件同等收益（沿用旧稿 §5，仍然成立）。

## 3. 需求清单（RQ，验收方式必须可核验）

### 3.1 可信基线（修订组——旧稿没有的部分）

| 编号 | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| RQ-101 | 计时排除客户端进程开销 | 高 | `SELECT 1` harness 自测 avg < 0.5 ms 并写入报告（G1） |
| RQ-102 | 主数据集为真实嵌入数据 | 高 | SIFT1M/GloVe 之一 + SHA256；官方 GT 交叉验证一致率 >99%（G2） |
| RQ-103 | 均匀随机数据仅作负向对照 | 高 | 文档明确其定位并引 Rand-Euclidean 先例 |
| RQ-104 | 参数回归官方公式 | 高 | lists=rows/1000（≤1M）/sqrt(rows)（>1M）；无出处魔数全删（G3） |
| RQ-105 | 统计效力 | 高 | QUERIES≥1000、每配置 ≥3 次重复报 min/median/max（G7） |
| RQ-106 | 环境元数据完整 | 高 | commit SHA / pgvector 版本 / 硬件 / GUC 快照（G8） |
