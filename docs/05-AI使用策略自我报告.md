# AI 使用策略自我报告

## 1. 使用边界

本项目使用 AI coding agent 做文件索引、候选方案比较、脚本草拟、报告结构整理和反向审查。AI 不获得远端端点凭据，不替代源码阅读、实验执行、哈希核验或最终数字判定。所有 headline 数字都由本仓库原始 CSV、日志和环境文件重新计算；报告中的延期项也保留，而不是由模型补齐。

## 2. 闭环一：初版 scaling law 被源码推翻

早期讨论把内存/收益关系压缩成过于简单的 scaling law：按实际行数、维度和 lists 估算即可。这个模型忽略了 pgvector 为目标采样容量预先分配 `samplesSize`，把 `T=max(10000,50*lists)` 与实际样本数 `N=min(rows,T)` 错误合并。初版公式因此在大 lists 或 rows<T 时失真。

修正动作由人完成：逐行对照 `ivfkmeans.c:277-299`、`ivfbuild.c:403-415`、`ivfflat.h` 和 `vector.h`，把 11 个分配量拆开；再用 `tools/verify_ivfflat_sizes.c` 固定目标 ABI。最终模型不是“让数字更像预期”，而是能逐组复现后端报错和原始 stderr。

## 3. 闭环二：两次数值修正

第一处，评审初始估计把 200,000/384d/lists=8192 写成约 6,838 MB。源码显示 samples 按目标容量 409,600 分配，模型修正为 7,147 MB；远端真实错误随后原文报告 7,147 MB。第二处，100,000/128d/lists=32768 的初始估计约 16,695 MB，同样漏掉目标样本容量，源码重算为 17,459 MB；`old-fail-04.log` 再次以 `memory required is 17459 MB` 背书。

这两次修正都遵循同一纪律：先指出差异来自哪一个源码分配，再运行后端验证；如果实测与推导不一致，就暂停结论而不是修改公式迎合预期。AI 的草稿和评审的表值都可以被推翻，源码和原始错误优先级更高。

## 4. 闭环三：被否决的建议

| 建议/候选 | 决定 | 理由与证据 |
|---|---|---|
| 手写 `_mm*`/`__m*` SIMD | 否决 | 上游已有自动向量化设计；本项目只恢复 Makefile CFLAGS，审计零 intrinsics |
| 把 7.32% query_work_mem 改善写成主成果 | 否决 | 预设门槛为 10%，该结果只作辅助控制 |
| 将首轮负载漂移矩阵纳入 headline | 否决 | ABBA 一对跨主机负载档位，稳定复跑才可用 |
| 用均匀随机图证明 ANN 排序优势 | 否决 | 数据分布不支持该算法排序结论，旧图移入历史附录 |
| 为缺失的 P95/P99 生成估计值 | 否决 | 本 run 只采集完整 workload 均值，尾延迟写入局限 |

## 5. 复核责任

AI 生成的路径、公式和文字都必须经过三类人工检查：源码路径是否真实存在；数字能否从 CSV/日志独立重算；措辞是否超出证据边界。最终交付的 commit、PDF、SHA256 清单和远端推送由人工确认。AI 的价值是加速检索和提出反例，结论责任仍由项目执行者承担。
